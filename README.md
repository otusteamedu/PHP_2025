## 1. Модульные тесты:

### 1.1. Валидация поля `card_number`

- Если card_number содержит менее 16 цифр (например 15), то тестируемый метод должен вернуть ошибку 400 "Неверный номер карты"
- Если card_number содержит более 16 цифр (например, 17), то тестируемый метод должен вернуть ошибку 400 "Неверный номер карты"
- Если card_number содержит буквы, то тестируемый метод должен вернуть ошибку 400 "Неверный номер карты"
- Если card_number содержит спецсимволы, то тестируемый метод должен вернуть ошибку 400 "Неверный номер карты"
- Если card_number пустой, то тестируемый метод должен вернуть ошибку 400 "Неверный номер карты"
- Если card_number содержит пробелы, то тестируемый метод должен вернуть ошибку 400 "Неверный номер карты"
- Если card_number корректный (16 цифр), то валидация поля успешна

### 1.2. Валидация поля `card_holder`

- Если card_holder содержит кириллицу, то тестируемый метод должен вернуть ошибку 400 "Неверное имя владельца"
- Если card_holder содержит цифры, то тестируемый метод должен вернуть ошибку 400 "Неверное имя владельца"
- Если card_holder содержит более одного пробела подряд, то тестируемый метод должен вернуть ошибку 400 "Неверное имя владельца"
- Если card_holder не содержит пробела (только имя), то тестируемый метод должен вернуть ошибку 400 "Неверное имя владельца"
- Если card_holder пустой, то тестируемый метод должен вернуть ошибку 400 "Неверное имя владельца"
- Если card_holder содержит спецсимволы кроме дефиса, то тестируемый метод должен вернуть ошибку 400 "Неверное имя владельца"
- Если card_holder корректный, то валидация поля успешна

### 1.3. Валидация поля `card_expiration`

- Если card_expiration в неверном формате, то тестируемый метод должен вернуть ошибку 400 "Неверный срок действия карты"
- Если card_expiration месяц > 12, то тестируемый метод должен вернуть ошибку 400 "Неверный срок действия карты"
- Если card_expiration месяц = 00, то тестируемый метод должен вернуть ошибку 400 "Неверный срок действия карты"
- Если card_expiration содержит буквы, то тестируемый метод должен вернуть ошибку 400 "Неверный срок действия карты"
- Если card_expiration пустой, то тестируемый метод должен вернуть ошибку 400 "Неверный срок действия карты"
- Если card_expiration карта просрочена (дата в прошлом), то тестируемый метод должен вернуть ошибку 400 "Срок действия карты истёк"
- Если card_expiration корректный (03/27), то валидация поля успешна

### 1.4. Валидация поля `cvv`

- Если cvv содержит менее 3 цифр, то тестируемый метод должен вернуть ошибку 400 "Неверный CVV-код"
- Если cvv содержит более 3 цифр, то тестируемый метод должен вернуть ошибку 400 "Неверный CVV-код"
- Если cvv содержит буквы, то тестируемый метод должен вернуть ошибку 400 "Неверный CVV-код"
- Если cvv содержит спецсимволы, то тестируемый метод должен вернуть ошибку 400 "Неверный CVV-код"
- Если cvv пустой, то тестируемый метод должен вернуть ошибку 400 "Неверный CVV-код"
- Если cvv корректный, то валидация поля успешна

### 1.5. Валидация поля `order_number`

- Если order_number содержит более 16 символов, то тестируемый метод должен вернуть ошибку 400 "Неверный номер заказа"
- Если order_number пустой, то тестируемый метод должен вернуть ошибку 400 "Неверный номер заказа"
- Если order_number корректный, то валидация поля успешна

### 1.6. Валидация поля `sum`

- Если sum отрицательная, то тестируемый метод должен вернуть ошибку 400 "Неверная сумма"
- Если sum равна нулю, то тестируемый метод должен вернуть ошибку 400 "Неверная сумма"
- Если sum содержит буквы, то тестируемый метод должен вернуть ошибку 400 "Неверная сумма"
- Если sum с точкой вместо запятой, то тестируемый метод должен вернуть ошибку 400 "Неверная сумма"
- Если sum пустая, то тестируемый метод должен вернуть ошибку 400 "Неверная сумма"
- Если sum корректная, то валидация поля успешна

### 1.7. Обработка ответа от Сервиса A используя моки

- Если сервис A возвращает ответ 200, то вызывается метод репозитория setOrderIsPaid
- Если сервис A возвращает ответ 403, то возвращается сообщение "Не удалось списать средства"
- Если сервис A недоступен (таймаут), ответ 503, то возвращается сообщение "Сервис временно недоступен"

### 1.8. Обработка ответа от репозитория используя моки

- Если setOrderIsPaid возвращает true, то ответ 200 и сообщение "Оплата прошла успешно"
- Если setOrderIsPaid возвращает false, то ответ 400 и сообщение "Ошибка при сохранении оплаты"
- Если setOrderIsPaid выбрасывает исключение OrderNotFoundException, то ответ 404 и сообщение "Заказ не найден"
- Если setOrderIsPaid выбрасывает исключение SumMismatchException, то ответ 400 и сообщение "Сумма не соответствует заказу"
- Если setOrderIsPaid выбрасывает исключение OrderAlreadyPaidException, то ответ 400 и сообщение "Заказ уже оплачен"

## 2. Интеграционные тесты:

### 2.1. Проверяем связку «Фронт — Бэк»

**Поведение фронта при ошибках:**

- Поле с ошибкой выделяется красной рамкой
- Под полем появляется текст ошибки
- Кнопка "Оплатить" остаётся активной для повторной попытки

**Кейсы для проверки:**

- Если невалидный card_number, то поле "Номер карты" выделяется красной рамкой, под ним текст "Неверный номер карты"
- Если невалидный cvv, то поле "CVV" выделяется красной рамкой, под ним текст "Неверный CVV-код"
- Если все поля валидны, то форма успешно отправляется на сервер и нет красных рамок
- Если бэк возвращает HTTP 403, то появляется сообщение об ошибке "Не удалось списать средства"
- Если бэк возвращает HTTP 503, то появляется сообщение об ошибке "Сервис временно недоступен"
- Если бэк возвращает HTTP 400, то появляется сообщение об ошибке "Ошибка при сохранении оплаты"
- Если бэк возвращает HTTP 404, то появляется сообщение об ошибке "Заказ не найден"
- Если бэк возвращает HTTP 200, то отображается сообщение "Оплата прошла успешно"
- Бэк недоступен (сетевая ошибка), то отображается сообщение "Ошибка соединения, попробуйте позже"

### 2.2. Проверяем связку «Бэк — Сервис A» (сервис A замокан и возвращает определённые ответы):

- В Сервис A отправляются корректных данных, то сервис A возвращает HTTP 200, бэк продолжает обработку
- В Сервис A отправляются данные карты с недостаточным балансом, то сервис A возвращает HTTP 403, бэк возвращает ошибку
- В сервис A отправляются данные заблокированной карты, то сервис A возвращает HTTP 403, бэк возвращает ошибку
- Если сервис A отвечает с задержкой (timeout), то бэк корректно обрабатывает таймаут и возвращает HTTP 503

### 2.3. Связка «Бэк — Репозиторий»:

- Вызов setOrderIsPaid с существующим заказом и корректной суммой, метод возвращает true, в БД записывается информация об оплате
- Вызов setOrderIsPaid с несуществующим заказом, то выбрасывается исключение OrderNotFoundException
- Вызов setOrderIsPaid с неверной суммой, то выбрасывается исключение SumMismatchException |
- Вызов setOrderIsPaid при недоступной БД, то выбрасывается исключение DatabaseException
- Повторный вызов setOrderIsPaid для уже оплаченного заказа, выбрасывается исключение OrderAlreadyPaidException |

## 3. Системные тесты

Тестирование полного потока: Фронт → Бэк → Сервис A → Бек → Репозиторий → Бек → Фронт

**Кейсы:**

- Успешная оплата с валидными данными, то пользователь видит сообщение "Оплата прошла успешно", заказ помечен оплаченным в БД
- Отправка формы с невалидным номером карты, то поле выделяется красной рамкой, форма не отправляется на Сервис A
- Оплата с невалидными реквизитами карты, то пользователь видит сообщение "Не удалось списать средства"
- Оплата картой с недостаточным балансом, то пользователь видит сообщение "Не удалось списать средства"
- Оплата с истёкшим сроком действия карты, то пользователь видит сообщение "Срок действия карты истёк", поле выделено красным
- Оплата несуществующего заказа, то пользователь видит сообщение "Заказ не найден"
- Попытка повторной оплаты уже оплаченного заказа, то пользователь видит сообщение "Заказ уже оплачен"
- Оплата при временной недоступности Сервиса A, то пользователь видит сообщение "Сервис временно недоступен"
