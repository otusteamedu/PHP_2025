# Приложение обработки отложенных запросов

## Текст задания

Необходимо реализовать Rest API с использованием очередей.

Ваши клиенты будут отправлять запросы на обработку, а вы будете складывать их в очередь и возвращать номер запроса.

В фоновом режиме вы будете обрабатывать запросы, а ваши клиенты периодически, используя номер запроса, будут проверять статус его обработки.


Разрешается

- Использование Composer-зависимостей

- Использование микрофреймворков (Lumen, Silex и т.п.)

## Краткое описание реализации

Приложение принимает JSON-запрос на обработку, сохраняет его в Postgres со статусом `queued`, отправляет идентификатор запроса в очередь RabbitMQ и сразу возвращает клиенту номер запроса.

Отдельный worker читает сообщения из RabbitMQ, переводит запрос в статус `processing`, ждет 30 секунд для имитации долгой обработки и затем ставит статус `completed`.

Для проверки ошибочного сценария каждая третья заявка завершается со статусом `failed`. Например, запросы с ID `3`, `6`, `9` получат ошибку обработки.


## Используемые сервисы

- `nginx` - веб-сервер;
- `app` - PHP-FPM приложение;
- `rabbitmq` - очередь сообщений;
- `postgres` - база данных для хранения запросов и статусов;
- `swagger-ui` - веб-интерфейс документации API.

## База данных

Postgres хранит запросы в таблице `requests`.

Основные поля:

- `id` - порядковый номер запроса;
- `title` - название запроса;
- `description` - описание запроса;
- `status` - кодовый статус обработки;
- `error_message` - текст ошибки обработки;
- `created_at` - дата создания;
- `updated_at` - дата последнего обновления;
- `processed_at` - дата завершения обработки.

Статусы обработки:

- `queued` - в очереди;
- `processing` - в обработке;
- `completed` - обработан;
- `failed` - ошибка обработки.

## Установка и запуск

Перед запуском необходимо создать файл `.env`. За основу можно взять пример из файла `.env.example` и указать в нем локальные настройки RabbitMQ и Postgres.

Собрать и запустить контейнеры:

```bash
docker-compose up -d --build
```

Установить Composer-зависимости внутри PHP-контейнера:

```bash
docker-compose exec app composer install --working-dir=/data/mysite.local
```

Открыть приложение:

```text
http://mysite.local
```

Для этого нужно добавить в hosts-файл запись:

```text
127.0.0.1 mysite.local
```

## Запросы API

Создать запрос на обработку:

```text
POST http://mysite.local/api/v1/requests
```

Пример тела запроса:

```json
{
  "title": "Загрузка отчета",
  "description": "Сформировать тестовый отчет по заявке"
}
```

Пример ответа:

```json
{
  "request_id": 1
}
```

Получить статус обработки:

```text
GET http://mysite.local/api/v1/requests/{request_id}
```

Пример:

```text
GET http://mysite.local/api/v1/requests/1
```

## Запуск worker

Worker запускается отдельной командой:

```bash
docker-compose exec app php /data/mysite.local/bin/worker.php
```

Он будет ждать сообщения из очереди RabbitMQ и обрабатывать их.

Основная очередь:

```text
requests
```

Очередь для ошибочных сообщений:

```text
requests_failed
```

## Проверка работы

1. Запустить контейнеры и установить Composer-зависимости.

2. Запустить worker:

```bash
docker-compose exec app php /data/mysite.local/bin/worker.php
```

3. Отправить `POST /api/v1/requests`.

4. Проверять статус через `GET /api/v1/requests/{request_id}`.

5. Если worker уже взял сообщение, статус сначала станет `processing`.

6. Через 30 секунд статус станет `completed`, если номер запроса не кратен 3.

7. Если номер запроса кратен 3, статус станет `failed`, а поле `error_message` будет содержать текст имитации ошибки.
