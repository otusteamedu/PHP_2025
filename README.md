## 2. Интеграционные тесты

### 2.1. Связка: Фронт - Бэк
2.1.1. `card_number` невалиден → Фронт получает код 400, поле `card_number` подсвечивается красной рамкой, отображается сообщение "Неверный формат..."<br>
2.1.2. `card_holder` невалиден → Фронт получает код 400, поле `card_holder` подсвечивается красной рамкой, отображается сообщение "Неверный формат..."<br>
2.1.3. `card_expiration` невалиден → Фронт получает код 400, поле `card_expiration` подсвечивается красной рамкой, отображается сообщение "Неверный формат..."<br>
2.1.4. `cvv` невалиден → Фронт получает код 400, поле `cvv` подсвечивается красной рамкой, отображается сообщение "Неверный формат..."<br>
2.1.5. `sum` невалидна → Фронт получает код 400, поле `sum` подсвечивается красной рамкой, отображается сообщение "Неверный формат..."<br>
2.1.6. Все данные валидны, СервисА возвращает 403 → Фронт получает код 403, отображается сообщение об ошибке оплаты<br>
2.1.7. Все данные валидны, СервисА возвращает 200, Репо возвращает true → Фронт получает код 200, отображается сообщение "Оплата успешна..."<br>

### 2.2. Связка: Бэк - СервисА
2.2.1. Бэк отправляет валидные данные карты в СервисА, СервисА возвращает код 200 → Бэк получает подтверждение, переходит к записи в Репо<br>
2.2.2. Бэк отправляет валидные данные карты в СервисА, СервисА возвращает код 403 → Бэк получает отказ, возвращает код 403 на Фронт, запись в Репо не производится<br>
2.2.3. Бэк отправляет данные в СервисА, СервисА недоступен (таймаут) → Бэк обрабатывает исключение, возвращает код 500 на Фронт<br>
2.2.4. Бэк отправляет невалидные данные (если бы валидация пропустила) → СервисА возвращает ошибку, Бэк транслирует её на Фронт<br>

### 2.3. Связка: Бэк - Репо

2.3.1. Бэк вызывает `setOrderIsPaid` с валидным `orderNumber` и `sum`, метод возвращает true → Бэк получает подтверждение, возвращает код 200 на Фронт<br>
2.3.2. Бэк вызывает `setOrderIsPaid` с `orderNumber`, которого нет в БД, метод выбрасывает исключение → Бэк перехватывает исключение, возвращает код 500 на Фронт<br>
2.3.3. Бэк вызывает `setOrderIsPaid` с неверной `sum`, метод возвращает false → Бэк получает false, возвращает код 500 на Фронт<br>

## 3. Системные тесты

3.1. Пользователь вводит валидные данные карты, нажимает "Оплатить" → Отображается сообщение "Оплата успешна...", деньги списываются с карты, данные корректно сохраняются в БД<br>
3.2. Пользователь проводит оплату с суммой, содержащей дробную часть → Оплата проходит успешно, сумма корректно записывается в БД<br>
<br>
3.3. На карте недостаточно средств (СервисА возвращает код 403) → Отображается сообщение "Не удалось списать...", статус заказа не меняется в БД<br>
3.4. Карта отклонена банком (СервисА возвращает 403) → Отображается сообщение "Не удалось списать...", статус заказа не меняется в БД<br>
3.5. СервисА временно недоступен (код 500) → Отображается сообщение "Сервис временно недоступен...", статус заказа не меняется в БД<br>
<br>
3.6. Пользователь ввёл невалидный номер карты → При нажатии "Оплатить" поле подсвечивается красным, сообщение "Неверный формат...", оплата не производится<br>
3.7. Пользователь ввёл невалидное имя владельца → При нажатии "Оплатить" поле подсвечивается красным, сообщение "Неверный формат...", оплата не производится<br>
3.8. Пользователь ввёл невалидный срок действия → При нажатии "Оплатить" поле подсвечивается красным, сообщение "Неверный формат...", оплата не производится<br>
3.9. Пользователь ввёл невалидный CVV → При нажатии "Оплатить" поле подсвечивается красным, сообщение "Неверный формат...", оплата не производится<br>
<br>
3.10. Пользователь дважды нажимает кнопку "Оплатить" (быстро-подряд) → Оплата проводится только один раз, деньги списываются 1 раз<br>
3.11. Пользователь оплатил заказ, затем попытался оплатить тот же заказ повторно → Система распознаёт уже оплаченный заказ, отображается сообщение "Заказ уже оплачен", повторное списание не производится<br>
<br>
3.12. После ошибки валидации пользователь исправляет данные и отправляет форму повторно → Оплата проходит успешно при валидных данных<br>
3.13. После временной недоступности сервиса A пользователь повторяет попытку через некоторое время → Оплата проходит успешно, когда СервисА становится доступен<br>
