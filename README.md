## Проблемы

Для выполнения задания взяла из проекта один класс-контроллер MeasureTable с одним методом get, который выполнял много разных функций (нарушение принципа единой ответственности).

1. Валидация пользователя и получение квартиры.

2. Получение и упорядочивание счетчиков.

3. Построение строк таблицы показаний для каждого счетчика.

4. Группировка результатов.


Кроме нарушения принципа единой ответственности, в классе есть еще несколько проблем:

* Жестко закодированные массивы.

* Использование глобальных функций.

* Использование анонимной функции.

* Нарушение принципа открытости-закрытости: добавление новых типов счетчиков требует изменения существующего кода.

* Нарушение DRY: дублирование кода для обработки разных типов счетчиков.

* Нарушение KISS: сложная логика в методе get.

## План решения

Для устранения этих проблем решила:

1. Разбить класс на несколько классов, каждый со своей ответственностью.

2. Вынести конфигурационные массивы (порядок моделей, названия, соответствия сигналов) в отдельные конфигурационные классы или константы.

3. Сделать классы открытыми для расширения (чтобы можно было добавить новые типы счетчиков, изменив конфигурационные массивы) и закрытыми для изменений. Для этого добавить фабрику по генерации объекта класса для нужного типа счетчика.

4. Глобальные функции вынести во вспомогательные классы.

Примечание: классы Infrastructure\Models - это классы по работе с БД. Показано только предполагаемое их размещение в проекте. Сами классы содержат только сигнатуры методов для наглядности.
