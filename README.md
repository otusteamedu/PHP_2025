# Приложение обработки отложенных запросов

## Текст задания

Пишем приложение обработки отложенных запросов.

1. Создать простое веб-приложение, принимающее POST запрос из формы от пользователя. Например, запрос на генерацию банковской выписки за указанные даты.

1.1. Обычно такие запросы в реальных системах работают довольно долго, поэтому пользователя надо оповестить о том, что запрос принят в обработку.

1.2. Форма должна подразумевать отправку оповещения по результатам работы.

2. Передать тело запроса в очередь.

3. Написать скрипт, который будет читать сообщения из очереди и выводить информацию о них в консоль.

4. Реализация оповещения.

4.1. Сгенерированный ответ отправить через email.

Приложить инструкцию по запуску системы.

Используем принципы SOLID. Перегружать и сильно мудрить не надо. Надо реализовать достаточный минимум для выполнения задания.

## Краткое описание реализации

Приложение принимает заявку на генерацию банковской выписки. Пользователь указывает номер счета, период выписки и, при желании, email.

После отправки формы веб-приложение кладет JSON-сообщение в очередь RabbitMQ и сразу сообщает пользователю, что запрос принят в обработку.

Данные формы проходят базовую валидацию, минимально необходимую для задания по практике работы с очередью и отложенной обработкой запроса.

Отдельный worker читает сообщения из очереди, выводит данные заявки в консоль, генерирует текст выписки и выбирает подходящие стратегии доставки:

- если email указан, выписка отправляется через SMTP в Mailpit;
- если email не указан, worker выводит сообщение о получении выписки в отделении банка.
- если при обработке сообщения произошла ошибка, исходное сообщение попадает в очередь `statement_requests_failed`.

Текст банковской выписки формируется стандартный: операции и суммы захардкожены и не являются реальными банковскими данными. Для задания это имитация долгой генерации выписки.

## Используемые сервисы

- `nginx` - веб-сервер;
- `app` - PHP-FPM приложение;
- `rabbitmq` - очередь сообщений;
- `mailpit` - локальный SMTP-сервер и веб-интерфейс для просмотра писем.

## Установка и запуск

Перед запуском необходимо создать файл `.env`. За основу можно взять пример из файла `.env.example` и указать в нем локальные настройки RabbitMQ, Mailpit и SMTP.

Собрать и запустить контейнеры:

```bash
docker-compose up -d --build
```

Установить Composer-зависимости внутри PHP-контейнера:

```bash
docker-compose exec app composer install --working-dir=/data/mysite.local
```

Открыть приложение:

```text
http://mysite.local
```

Для этого нужно добавить в hosts-файл запись:

```text
127.0.0.1 mysite.local
```

## Полезные адреса

RabbitMQ Management UI:

```text
http://localhost:15672
```

Mailpit, веб-интерфейс локального почтового сервера:

```text
http://localhost:8025
```

## Запуск worker

Worker запускается отдельной командой:

```bash
docker-compose exec app php /data/mysite.local/bin/worker.php
```

Он будет ждать сообщения из очереди RabbitMQ и обрабатывать их.

Основная очередь:

```text
statement_requests
```

Очередь для ошибочных сообщений:

```text
statement_requests_failed
```

## Проверка работы

1. Открыть приложение:

```text
http://mysite.local
```

2. Заполнить форму:

- email, необязательное поле;
- номер счета;
- дата начала периода;
- дата окончания периода.

3. Нажать кнопку `Отправить запрос`.

4. На странице должно появиться сообщение, что запрос принят в обработку.

5. Запустить worker:

```bash
docker-compose exec app php /data/mysite.local/bin/worker.php
```

6. В консоли worker должно появиться сообщение о полученном запросе:

- ID заявки;
- email или текст `не указан`;
- номер счета;
- период выписки.

7. Если email был указан, открыть интерфейс локального почтового сервера Mailpit:

```text
http://localhost:8025
```

8. В Mailpit должно появиться сгенерированное письмо с банковской выпиской.
