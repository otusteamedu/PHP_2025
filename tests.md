2. Обработка ответов от зависимостей:

- Если сервис A возвращает HTTP 200 - метод продолжает выполнение
- Если сервис A возвращает HTTP 403 - метод возвращает HTTP 403 с сообщением об ошибке
- Если сервис A возвращает HTTP 500 - метод возвращает HTTP 500 с сообщением об ошибке
- Если метод setOrderIsPaid возвращает true - метод возвращает успешный ответ HTTP 200
- Если метод setOrderIsPaid отдает исключение (любое) - метод возвращает HTTP 500 с сообщением об ошибке

3. Интеграционные тесты

3.1 Фронтенденд-Бэкенд:

- Если card_number невалиден - фронтенд выделяет поле "Номер карты" красной рамкой
- Если card_holder невалиден - фронтенд выделяет поле "Владелец карты" красной рамкой
- Если сервис A возвращает HTTP 403 - фронтенд показывает сообщение "Не удалось списать данные с карты, проверьте реквизиты"
- Если репозиторий отдает исключение - фронтенд показывает сообщение "Внутренняя ошибка сервера"

3.2 Бэкенд-Сервис A:

- Проверка, что все валидные данные передаются в Сервис A в правильном формате
- Проверка обработки ответа HTTP 403 от Сервиса A и передачи его на фронтенд

3.3 Бэкенд-репозиторий:

- Проверка, что метод setOrderIsPaid вызывается с правильными параметрами после успешного ответа от Сервиса A
- Проверка, что исключение из репозитория корректно преобразуется в HTTP 500

4. Системные тесты

- Если cvv неверен - после получения ответа от бэка на фронтенде выводится сообщение об ошибке "Не удалось списать данные с карты, проверьте реквизиты"
- Если все данные корректны и сервис A возвращает успех - происходит успешная оплата и показывается сообщение "Оплата прошла успешно"
- Если сервис A недоступен - показывается сообщение "Платёжный сервис временно недоступен, попробуйте позже"
- Если сумма не соответствует сумме заказа в БД - показывается сообщение "Произошла ошибка, обратитесь в поддержку"
