## SERIAL

Типы данных smallserial, serial и bigserial не являются настоящими типами, а представляют собой просто удобное средство для создания столбцов с
уникальными идентификаторами (подобное свойству AUTO_INCREMENT в некоторых СУБД).
Для создания столбца с типом данных serial в PostgreSQL, вы можете использовать ключевое слово SERIAL при объявлении столбца, например:

```
CREATE TABLE users (
    id SERIAL PRIMARY KEY,
    name VARCHAR(50),
    email VARCHAR(100)
);
```

Это создаст столбец id, который будет автоматически генерировать уникальные целочисленные значения при каждой вставке новой записи в таблицу пользователей. Кроме того, указание PRIMARY KEY после SERIAL гарантирует уникальность значений в столбце и делает его первичным ключом для таблицы.

Serial в PostgreSQL обеспечивает удобный способ создания автоинкрементного столбца в таблице, что делает его популярным выбором для идентификации записей и обеспечения уникальности значений в базе данных.

## CHECK
Ограничение-проверка — наиболее общий тип ограничений. В его определении вы можете указать, что значение данного столбца должно удовлетворять логическому выражению (проверке истинности). 


```CREATE TABLE products (
    product_no integer,
    name text,
    price numeric CHECK (price > 0)
);```

## IS

В контексте SQL-команды COMMENT ON, ключевое слово IS не является самостоятельным оператором. Оно является частью фиксированной синтаксической конструкции, которая связывает объект базы данных с текстом комментария.
Если проводить аналогию с человеческим языком, то IS здесь работает как связка «это» или «является».

## UNIQUE INDEX

Ограничения уникальности гарантируют, что данные в определённом столбце или группе столбцов уникальны среди всех строк таблицы. Ограничение записывается так:
CREATE TABLE products (
    product_no integer UNIQUE,
    name text,
    price numeric
);

Чтобы определить ограничение уникальности для группы столбцов, запишите его в виде ограничения таблицы, перечислив имена столбцов через запятую:

CREATE TABLE example (
    a integer,
    b integer,
    c integer,
    UNIQUE (a, c)
);

## CONSTRAINT

https://habr.com/ru/companies/postgrespro/articles/672004/

Ограничения (Constraints) в PostgreSQL — это правила, применяемые к столбцам или таблицам для обеспечения целостности и корректности данных. Они предотвращают вставку недопустимых значений, гарантируя, что данные соответствуют бизнес-логике. Основные типы: NOT NULL, UNIQUE, PRIMARY KEY, FOREIGN KEY, CHECK. 
Основные типы ограничений (Constraints):
NOT NULL: Гарантирует, что столбец не содержит значений NULL.
UNIQUE: Обеспечивает уникальность значений в столбце или группе столбцов.
PRIMARY KEY: Уникально идентифицирует каждую строку, сочетая свойства UNIQUE и NOT NULL.
FOREIGN KEY: Поддерживает ссылочную целостность между таблицами.
CHECK: Проверяет, удовлетворяют ли значения логическому условию.
EXCLUDE: Гарантирует, что если любые две строки сравниваются, не все сравнения окажутся истинными (часто используется для предотвращения пересечений диапазонов).

Constraint в PostgreSQL - это ограничение, которое можно применить к столбцам таблицы для обеспечения целостности данных и выполнения бизнес-правил. Ограничения могут быть различных типов, таких как уникальность, нулевое значение, внешний ключ, проверочное условие и ограничение диапазона.

Например, уникальное ограничение может быть использовано для гарантирования, что значение в столбце не повторяется во всей таблице. Ограничение нулевого значения требует, чтобы определенный столбец не мог содержать NULL значения. Внешние ключи используются для связывания столбцов с другими таблицами и обеспечения целостности ссылочной целостности.

Ограничения могут быть добавлены при создании таблицы с помощью оператора CREATE TABLE или изменены позже с помощью оператора ALTER TABLE. Они играют важную роль в поддержании целостности данных в базе данных PostgreSQL.

Запись CONSTRAINT fk_halls_places_hall_id — это объявление имени для ограничения целостности (правила), которое вы накладываете на столбец.
Разберем по частям:
CONSTRAINT (Ограничение) — ключевое слово, которое говорит базе данных: «Внимание, сейчас я опишу правило, которое нельзя нарушать».
fk_halls_places_hall_id — это произвольное имя (алиас), которое вы даете этому правилу. Оно нужно, чтобы вы или СУБД могли обратиться к конкретному ограничению позже.

## FOREIGN KEY

Foreign Key (внешний ключ) в PostgreSQL — это ограничение целостности, связывающее столбец одной таблицы (зависимой) с первичным или уникальным ключом другой (главной). Оно гарантирует ссылочную целостность, запрещая удаление данных из главной таблицы, если на них ссылаются в зависимой, и обеспечивая соответствие данных. 

## REFERENCES

REFERENCES в PostgreSQL — это ключевое слово, используемое при создании внешних ключей (FOREIGN KEY) для обеспечения ссылочной целостности между таблицами. Оно указывает, что данные в одном столбце должны соответствовать значениям в столбце другой (родительской) таблицы, гарантируя отсутствие «сиротских» записей.
