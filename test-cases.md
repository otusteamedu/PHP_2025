# Кейсы тестирования

## Unit Тесты

### card_holder

1. Если `card_holder` содержит более одного пробела, то тестируемый метод возвращает 400 с сообщением об ошибке;
2. Если `card_holder` содержит любые символы кроме символов латинского алфавита, пробела и дефисов, то тестируемый метод возвращает 400 с сообщением об ошибке
3. Если `card_holder` пустой, то тестируемый метод возвращает 400 с сообщением об ошибке
4. Если `card_holder` содержит слова написанные латиницей с пробелами(не подряд) или дефисами (не подряд) ("John Doe", "Mikhail Saltykov-Shchedrin"), ошибки нет

### card_number
- Если `card_number` пустой, то тестируемый метод возвращает 400 с сообщением об ошибке
- Если `card_number` содержит буквы или другие символы (кроме цифр), то тестируемый метод возвращает 400 с сообщением об ошибке;
- Если `card_number` длиннее или короче 16 символов (15, 17), то тестируемый метод возвращает 400 с сообщением об ошибке
- Если `card_number` содержит только цифры и имеет длину 16 символов, то ошибки нет

### card_expiration
1. Если `card_expiration` пустой, то тестируемый метод возвращает 400 с сообщением об ошибке
2. Если `card_expiration` содержит любые символы кроме цифр и косой черты, то тестируемый метод возвращает 400 с сообщением об ошибке
3. Если `card_expiration` длиннее 5 символов, то тестируемый метод возвращает ошибку
4. Если формат не "мм/гг" (напр., "13/25", "00/25", "12/2"), то тестируемый метод возвращает 400 с сообщением об ошибке
5. Если число "мм" `card_expiration` меньше 1 или больше 12, то тестируемый метод возвращает 400 с сообщением об ошибке
6. Если срок действия карты истек (напр., "01/22" при текущей дате "03/24"), то тестируемый метод возвращает 400 с сообщением об ошибке (в текущих реалиях работы с продленными Visa и MasterCard возможно не стоит проверять на истекший срок)
7. Если срок действия корректен, ошибки нет.

### CVV
1. Если `cvv` пустой, то тестируемый метод возвращает 400 с сообщением об ошибке
1. Если `cvv` содержит любые символы кроме цифр, то тестируемый метод возвращает 400 с сообщением об ошибке
2. Если длина `cvv` не равна 3, то тестируемый метод возвращает 400 с сообщением об ошибке 
3. Если `cvv` содержит только цифры и имеет длину 3 символа, то ошибки нет

### Sum
1. Если `sum` меньше или равно 0, то тестируемый метод возвращает 400 с сообщением об ошибке
2. Если `sum` содержит любые символы кроме цифр и запятой, то тестируемый метод возвращает 400 с сообщением об ошибке
3. Если `sum` содержит больше 1 запятой, то тестируемый метод возвращает 400 с сообщением об ошибке
4. Если `sum` запятая находится в начале или конце строки, то тестируемый метод возвращает 400 с сообщением об ошибке
5. Если `sum` имеет корректный формат (1 запятая, разделитель целой и дробной части, запятая находится между цифрами), то ошибки нет

### Репозиторий
1. Если сумма заказа и номер заказа соответствуют, `setOrderIsPaid` возвращает true, клиенту возвращается 200
2. Если сумма заказа не соответствует номеру заказа, `setOrderIsPaid` выбрасывает исключение, клиенту возвращается ошибка 500 или 400
3. Если передается номер заказа, который отсутствует в базе, `setOrderIsPaid` выбрасывает исключение, клиенту возвращается ошибка 400

### Взаимодействие с Сервисом A:
1. Если сервис A (используется Mock) возвращает 200, вызывается метод setOrderIsPaid и возвращается 200.
2. Если сервис A (Mock) возвращает 403, метод setOrderIsPaid не вызывается, и возвращается 403 с сообщением от сервиса.


## Интеграционные тесты

### Связка фронт-бэк

1. Если card_holder содержит более одного пробела, то после получения ответа от бэка на фронте выделяется поле «Номер карты» красной рамкой;
2. Если card_number содержит менее 16 символов, то после получения ответа от бэка на фронте выделяется поле «Номер карты» красной рамкой;
3. При получении 403 от бэка фронт показывает общее сообщение "Не удалось провести оплату. Проверьте реквизиты или попробуйте позже." (Без указания конкретной причины в целях безопасности).
4. При отправке валидных данных и получении 200 от бэка фронт показывает сообщение "Оплата прошла успешно" и скрывает форму оплаты.


### Связка «Бэк-Сервис A»
Для снижения стоимости тестов рекомендуется использовать тестовый API сервиса А, использовать специальные тестовые карты сервиса А.
1. Бэк отправляет корректно сформированный HTTPS-запрос с нужными заголовками и телом. В ответ на 200 от Сервиса А бэк вызывает метод setOrderIsPaid(string
$orderNumber, float $sum) Мока Репозитория.
2. Бэк отправляет данные с недостаточным балансом. В ответ на 403 бэк формирует ответ для фронта и не вызывает метод setOrderIsPaid.
3. Бэк отправляет данные с некорректным CVV. В ответ на 403 бэк формирует ответ для фронта и не вызывает метод setOrderIsPaid.


### Связка Бэк-Репозиторий
В данном случае используется Мок сервиса А
1. После ответа 200 от Сервиса A (Мок) метод setOrderIsPaid вызывается с корректными параметрами и запись в БД появляется с статусом "оплачено".
2. После 200 от Сервиса A (Мок) метод setOrderIsPaid выбрасывает исключение (напр., "Сумма по заказу не совпадает"). Бэк ловит его, обрабатывает и возвращает ответ клиенту



## Системные тесты
1. Если введенный cvv короче 3 символов, то после получения ответа от бэка на фронте выделяется поле "cvv" красной рамкой.
2. Если cvv неверен (не соответствует карте), то после получения ответа от бэка на фронте выводится сообщение об ошибке «Не удалось списать данные с карты, проверьте реквизиты».
3. Если card_expiration указывает на прошедший срок, то после получения ответа от бэка на фронте выводится сообщение об ошибке «Срок действия карты истёк»;
4. Если на карте недостаточно средств, то заказ не проходит, на фронте отображается сообщение, что у пользователя недостаточно средств для проведения операции 
5. Если все данные корректны и оплата проходит успешно, то на фронте отображается сообщение «Оплата прошла успешно», и пользователь переадресуется на страницу фильма;
