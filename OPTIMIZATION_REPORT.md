# Отчет об оптимизации базы данных кинотеатра

## Что это за документ

Это простое описание работ, которые были сделаны для ускорения работы базы данных кинотеатра. База хранит информацию о фильмах, сеансах, проданных билетах и клиентах.

## В чем была проблема

База данных стала работать медленно, потому что в ней накопилось очень много записей (миллионы билетов). Когда кто-то спрашивал информацию, базе приходилось долго искать ответ.

---

## Что мы сделали

### 1. Добавили индексы

**Что такое индекс простыми словами:**
Представьте большую книгу без оглавления. Чтобы найти нужную тему, придется листать все страницы подряд. А если есть оглавление — сразу открываете нужную страницу. Индексы в базе данных работают точно так же.

### Какие индексы создали:

#### 1) Индекс для поиска сеансов по дате
- **Зачем:** Чтобы быстро показывать, какие фильмы идут сегодня
- **Результат:** Вместо просмотра всех сеансов, база сразу находит только сегодняшние

#### 2) Индекс для подсчета проданных билетов
- **Зачем:** Чтобы быстро посчитать, сколько билетов продано за неделю
- **Фишка:** Индекс хранит только проданные билеты (не забронированные, не отмененные)
- **Результат:** База смотрит только на проданные билеты, а не на все подряд
#### 3) Индекс для расчета выручки по фильмам
- **Зачем:** Чтобы быстро узнать, какой фильм принес больше всего денег
- **Фишка:** Опять же смотрим только проданные билеты, не все подряд
- **Результат:** Быстро считается общая сумма по каждому фильму

#### 4) Индекс для схемы зала (свободные места)
- **Зачем:** Чтобы сразу видеть, какие места в зале заняты, а какие свободны
- **Фишка:** Индекс знает только про проданные и забронированные места
- **Результат:** Не нужно проверять отмененные и возвращенные билеты

#### 5) Индекс для поиска минимальной и максимальной цены билета
- **Зачем:** Чтобы быстро показать самый дешевый и самый дорогой билет на сеанс
- **Результат:** Не нужно просматривать все билеты, чтобы найти минимум и максимум

---

### 2. Обновили статистику

**Что это значит:**
База данных сама решает, как лучше искать информацию. Для этого ей нужна статистика — сколько записей в таблице, какие значения встречаются чаще. После того как мы добавили миллионы записей, нужно было сказать базе: "Эй, посчитай заново статистику!". Мы это сделали.

**Результат:** База теперь знает реальные размеры таблиц и может выбирать оптимальный способ поиска.

---

### 3. Переписали некоторые запросы

Некоторые запросы были написаны так, что база не могла использовать индексы. Мы их переписали по-другому.

**Пример:**
- **Было:** "Найди сеансы, где день равен сегодняшнему" (база не знает, как использовать индекс)
- **Стало:** "Найди сеансы, где время больше начала сегодняшнего дня и меньше завтрашнего" (база использует индекс!)

---

### 4. Дали рекомендации по настройкам базы

Рассказали, какие настройки PostgreSQL можно подкрутить для еще большей скорости:
- Увеличить память для сортировок
- Включить параллельную обработку (использовать несколько процессоров одновременно)
- Настроить параметры для современных SSD дисков

## Какие запросы мы оптимизировали

Всего было 6 главных запросов, которые работали медленно:

### Запрос 1: Какие фильмы идут сегодня
- **Суть:** Показать список всех фильмов, которые показывают сегодня
- **Как ускорили:** Создали индекс по времени сеанса, теперь база сразу находит сегодняшние сеансы

### Запрос 2: Сколько билетов продано за неделю
- **Суть:** Посчитать количество проданных билетов
- **Как ускорили:** Индекс хранит только проданные билеты, не нужно смотреть все подряд

### Запрос 3: Афиша кинотеатра на сегодня
- **Суть:** Показать полное расписание — какой фильм, в каком зале, во сколько
- **Как ускорили:** Индекс помогает быстро объединить информацию из нескольких таблиц

### Запрос 4: Топ-3 самых прибыльных фильма
- **Суть:** Узнать, какие фильмы принесли больше всего денег за неделю
- **Как ускорили:** Индекс по проданным билетам и их ценам ускоряет подсчет выручки

### Запрос 5: Схема зала с занятыми местами
- **Суть:** Показать, какие места свободны, какие заняты на конкретном сеансе
- **Как ускорили:** Индекс знает только про занятые места, не проверяет отмененные билеты

### Запрос 6: Минимальная и максимальная цена билета
- **Суть:** Узнать самый дешевый и самый дорогой билет на сеанс
- **Как ускорили:** Индекс по ценам позволяет найти минимум и максимум без просмотра всех билетов

### Чем хороши частичные индексы

Некоторые индексы мы сделали "частичными" — они хранят не все записи, а только нужные. Например, индекс только для проданных билетов, без забронированных и отмененных.

**Плюсы:**
- Занимают меньше места на диске
- Работают быстрее
- Легче обновляются при добавлении новых записей

## Что можно сделать дальше

### 1. Понаблюдать за индексами

Через пару недель проверить, все ли индексы реально используются. Если какой-то индекс не нужен — удалить его, чтобы не тратить место.

### 2. Разбить большую таблицу на части (партиционирование)

Таблица с билетами очень большая. Можно разбить ее по месяцам: январь в одну таблицу, февраль в другую и так далее. Тогда при поиске база будет смотреть только нужный месяц, а не все месяцы подряд.

### 3. Создать готовые отчеты (материализованные представления)

Некоторые данные запрашиваются очень часто (например, афиша на сегодня). Можно один раз посчитать такой отчет, сохранить его и показывать готовым. Обновлять раз в час или когда добавляется новый сеанс.

### 4. Настроить кэширование

Часто запрашиваемые данные можно временно хранить в памяти (кэш), чтобы вообще не обращаться к базе каждый раз. Например:
- Афишу на сегодня хранить 10 минут
- Топ фильмов хранить 1 час

### 5. Регулярное обслуживание базы

Время от времени нужно:
- Обновлять статистику
- Чистить базу от "мусора" (старых удаленных записей)
- Проверять размеры таблиц и индексов

## Как проверить результаты

Если хотите убедиться, что оптимизация работает, нужно:

1. Создать базу данных (запустить файл `films_DDL.sql`)
2. Загрузить тестовые данные (запустить файл `DML_10000000.sql`)
3. Применить оптимизации (запустить файл `optimizations.sql`)
4. Проверить планы выполнения запросов (запустить файл `EXPLAIN_10000000_optimized.sql`)
5. Посмотреть метрики (запустить файл `db_metrics.sql`)

Все эти файлы уже готовы и лежат в проекте.
