## Задание
Разрабатываем часть интернет-ресторана. Продаёт он фаст-фуд.

1. Стратегия будет отвечать за генерацию базового продукта: бургер, сэндвич или хот-дог
2. При готовке каждого типа продукта Декоратор будет добавлять составляющие к базовому продукту либо по рецепту, либо по пожеланию клиента (салат, лук, перец и т.д.)
3. Наблюдатель позволит подписываться на события изменения заказа, чтобы отправлять push-уведомления и sms
4. Шаблонный метод используется для навешивание пре и пост событий на процесс готовки. Например, если бургер не соответствует стандарту, пост событие утилизирует его.
5. Строитель будет формировать заказ и двигать его по статусам приготовления 
6. Все сущности должны по максимуму генерироваться через DI.

## Демо
Для наглядности реализовано демо, в котором представлены:

- создание заказа
- подписку на уведомления (push, sms)
- добавление продуктов по рецепту (Бургер) и с пожеланиями клиента (Хот-дог)
- переход заказа по статусам
- проверку качества готового продукта
- утилизацию одного из продуктов, который не соответствует стандарту

## Запуск демо

```bash

```
