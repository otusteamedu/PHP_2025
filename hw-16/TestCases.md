1. Длина ≠ 16 символов → 400  
2. Содержит нецифровые символы → 400  
3. Пустое значение → 400  
4. Поле отсутствует → 400  

---

8. Пустое значение → 400  
9. Поле отсутствует → 400

# 2. Интеграционные тесты

## 2.1 Связка «Фронт — Бэк»

1. Если card_number содержит 15 цифр →  
   бэк возвращает 400 →  
   фронт подсвечивает поле «Номер карты» красной рамкой.

2. Если card_expiration просрочен →  
   фронт подсвечивает поле «Срок действия».

3. Если сервис A возвращает 403 →  
   фронт выводит сообщение:  
   **«Не удалось списать средства. Проверьте реквизиты карты.»**

4. Если бэк возвращает 500 →  
   фронт выводит сообщение:  
   **«Произошла техническая ошибка. Попробуйте позже.»**

---

## 2.2 Связка «Бэк — Сервис A»

1. При корректных данных бэк отправляет корректный JSON в сервис A.  
2. Если сервис A возвращает 403 → бэк возвращает 403 без изменения кода.  
3. Если сервис A возвращает 200 → бэк вызывает репозиторий.

---

## 2.3 Связка «Бэк — Репозиторий»

1. Если репозиторий возвращает true → бэк возвращает 200  

2. Если репозиторий выбрасывает исключение → бэк возвращает 500  

---

# 3. Системные тесты

## 3.1 Успешная оплата

Пользователь вводит корректные данные →  
Сервис A возвращает 200 →  
В БД заказ помечается как оплаченный →  
Фронт выводит сообщение:

**«Оплата прошла успешно.»**

---

## 3.2 Ошибка списания

Пользователь вводит корректные данные →  
Сервис A возвращает 403 →  
В БД запись не создаётся →  
Фронт выводит сообщение:

**«Не удалось списать средства. Проверьте реквизиты карты.»**

---

## 3.3 Ошибка записи в БД

Сервис A возвращает 200 →  
Репозиторий выбрасывает исключение →  
В БД заказ не помечается как оплаченный →  
Фронт выводит сообщение:

**«Произошла техническая ошибка. Попробуйте позже.»**

---
